# Rein Room × Playwright 延伸應用規劃

Playwright 可以控制真實 Chrome 瀏覽器，對 RR 這種純前端平台幾乎沒有盲區。
以下整理從「現在就能做」到「需要額外整合」的各種應用方向。

---

## 一、自動化測試與品質保證

### 1-1 邊界情況壓力測試
自動生成各種「人工很難想到」的操作組合，例如：
- 載入遊戲途中切換演算法
- 清空記憶後立刻切 DQN 模式
- 暫停中途換遊戲再繼續
- 快速連續切換繪製資料來源
- 高速連點「清空」後立即「載入 JSON」

腳本幾秒內跑完所有排列，log 裡若出現 `fit 異常中止` 或知識同步卡在「神經網路建立中」，即可定位問題。

### 1-2 Console + stat 全量紀錄
```python
page.on("console", lambda msg: log(f"[{msg.type}] {msg.text}"))
```
攔截所有 Worker log、fitDone loss、錯誤訊息，搭配每步操作前後的 stat 快照（經驗覆蓋、知識同步率），形成完整行為紀錄，供我讀 log 找問題、修程式、重跑。

### 1-3 迴歸測試套件
每次推新版前跑一遍標準測試腳本，確認核心功能沒有壞掉：
- 五款遊戲都能正常載入並收到 gameInfo
- Qt 模式背景蒸餾迴圈有在跑（知識同步率有在上升）
- DQN 模式每回合末有 fitDone
- 清空後重新學習正常啟動

## 二、論文截圖與視覺資產生產

### 2-1 條件觸發截圖
等待特定狀態達成再截圖，確保每張圖都有意義：
```python
# 等知識同步率超過 90% 再截
while True:
    sync = await page.inner_text('#stat-sync')
    if float(sync.replace('%','')) > 90:
        await page.screenshot(path="sync_90.png")
        break
    await asyncio.sleep(2)
```

### 2-2 可重現截圖流程
固定超參數 → 固定遊戲 → 跑固定回合數 → 截圖，
每次都能產出狀態一致的圖片，論文圖片的可重現性大幅提升。

### 2-3 對照組截圖自動化
實驗的 A/B 兩組，用腳本在相同條件下各跑一次，自動截出對比圖，
避免人工截圖時兩組狀態不一致的問題。

## 三、錄影與展示

### 3-1 訓練過程錄影（Playwright 原生）
```python
context = await browser.new_context(record_video_dir="videos/")
```
一行設定，整個瀏覽器操作自動存成 `.webm`，
可用於論文附錄、課堂展示、或社群平台發布。

### 3-2 定點錄影（特定元素）
只錄 Q-Table 熱力圖區域，呈現策略從空白到收斂的完整過程，
比全螢幕錄影更聚焦、檔案更小。

### 3-3 Timelapse 生成
每 N 秒截一張圖，訓練結束後用 FFmpeg 串成縮時影片，
展示「從零學習到知識同步 95%」的完整歷程。

## 四、YouTube 直播自動化

### 4-1 FFmpeg 推流方案
```
Playwright 控制 RR 訓練
    ↓
FFmpeg 擷取畫面 + 推 RTMP 到 YouTube 串流金鑰
```
不需修改 RR 平台，純外部工具串接。

### 4-2 WHIP 瀏覽器端推流方案（對應 TODO.md 規劃）
透過 YouTube Data API 建立直播 → 取得 WHIP endpoint →
在 RR 頁面內用 `getDisplayMedia()` + WebRTC 直接推流，
符合 RR 純前端架構，不需後端伺服器。

### 4-3 直播自動標記
訓練達到里程碑時（如知識同步突破 50%、第一次通關），
自動呼叫 YouTube API 插入章節標記，讓觀看者能直接跳到關鍵時刻。

## 五、實驗數據自動收集

### 5-1 定時抓取 stat 寫進 CSV
```python
with open('experiment_log.csv', 'w') as f:
    while training:
        cover = await page.inner_text('#stat-cover')
        sync  = await page.inner_text('#stat-sync')
        f.write(f"{time.time()},{cover},{sync}\n")
        await asyncio.sleep(5)
```

### 5-2 跨遊戲對比實驗
自動在各遊戲上跑相同回合數，收集覆蓋率與知識同步率的成長曲線，
輸出成統一格式 CSV，直接匯入論文的統計分析。

### 5-3 超參數掃描實驗
自動測試 α / γ / ε 的不同組合，記錄每組的收斂速度，
類似機器學習的 hyperparameter search，但對象是 RL 的教學效果。

## 六、教學展示自動化

### 6-1 課堂 Demo 腳本
預先錄製「最理想的操作流程」腳本，上課時一鍵播放，
不受網路、操作失誤等現場因素影響，確保展示效果穩定。

補充：若 RR 前端加入假游標層，錄影版 MVP 建議聚焦在：
- 假游標移動
- 點擊波紋
- hover 高亮
- 拖曳路徑
- 標紅框聚焦

其中「步驟說明文字」可留給 FFmpeg 後製字幕，不必先做進頁面內。

### 6-2 互動式教學引導
學生操作 RR 時，Playwright 在背景監測，
若偵測到特定錯誤行為（如探索率調到 0、知識同步長時間不動），
自動彈出提示或截圖記錄，輔助教師後續分析。

## 七、自動生成教學影片

### 7-1 完整流水線
```
Playwright 分段錄製操作（每個功能一段）
    ↓
腳本自動生成旁白文稿（對應操作段落）
    ↓
TTS 合成語音（Azure / Google TTS / ElevenLabs）
    ↓
FFmpeg 合併影片 + 語音 + 字幕
    ↓
輸出完整教學影片
```

### 7-2 模組化段落設計
每個功能對應一段獨立錄影 + 獨立旁白：
- 「這是超參數調整區，α 控制學習速度…」
- 「切換到分析頁，這裡可以看到 Q-Table 熱力圖…」
- 「知識同步率代表神經網路與 Q-Table 的對齊程度…」

RR 更新功能時，只需重錄受影響的段落，其他段落照舊拼接，不需整片重來。

### 7-3 多語言版本
同一份操作錄影，搭配不同語言的 TTS 語音，
自動輸出中文版、英文版教學影片，適合國際場合或論文附錄。

### 7-4 客製化教案影片
根據課程設計，腳本選擇性組合段落：
- 入門版：MAB → Maze1D → 基本圖表解讀
- 進階版：CartPole → DQN 切換 → 知識同步觀察

不同教學對象產出不同版本，全自動。

## 八、YouTube 內容自動化系統

### 8-1 完整上傳流程
與第七章教學影片流水線串接，影片產出後自動上傳：
```
FFmpeg 合成影片
    ↓
YouTube Data API v3 上傳
設定標題 / 說明 / 標籤 / 縮圖 / 隱私設定
    ↓
回傳影片 ID，記錄進資料庫
```

### 8-2 成效監控
定期抓取所有已上傳影片的數據，輸出報表：
- 觀看數、按讚數、留言數
- 各影片成長趨勢對比
- 哪類內容表現最好，回饋給下一支影片的企劃

### 8-3 費用
- YouTube Data API v3：**免費**（每日 10,000 單位配額，上傳一支約 1,600 單位）
- Google Cloud Console：**免費**（需綁信用卡驗證身份，不扣款）
- 對教學展示用途完全夠用
