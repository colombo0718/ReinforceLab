# 規劃：動作選擇機率分布視覺化

> 目標：在現有「動作價值柱狀圖」（`p1-bars-value`）上，疊加 ε-greedy 與 Softmax 的機率分布，
> 並同步修正 A0 色彩邏輯，使動作色環、熱力圖、柱狀圖三處顏色完全統一。

---

## 背景：目前的問題

### 問題 A — 柱狀圖資訊量不足
`generateQBarSlice()` 只顯示 Q 值，看不出當前策略實際選動作的機率。

### 問題 B — A0 顏色邏輯例外
`generateDiscreteColorscale()` 把 A0 寫死為黑色，其餘動作才進入 HSV 色環。
但動作色環 SVG 把 A0 顯示在中心（視覺上是黑點），與「均分色環」的概念衝突。
ReinRoom 的遊戲沒有一個真正把 A0 用作「無動作」，這個特化沒有語意依據。

### 問題 C — epsilonToTau 設計本身沒有道理（BUGS.md #3，已修方向，待拆除耦合）
原本公式把 τ 綁定在 ε 上，是偷懶的設計。兩個超參數的語意完全不同：
- ε 控制「有多少機率不走最佳動作」
- τ 控制「Q 值差距多大才算有差」

此外 Softmax 對 Q 值尺度非常敏感：RR 平台的 Q 值量級在訓練後期可達 50~500，
`exp(Q/τ)` 在 τ 過小時直接溢出，最佳動作拿走全部機率，跟貪婪沒有區別。

**決策：Softmax 的行為（到最後機率趨向 1）本身是合理的，不修正。**
訓練後期 Q 值差距已經穩定，Softmax 最終收斂到幾乎確定性選擇是正確的。
重點是讓使用者能**獨立調整 τ**，而不是透過 ε 間接影響。

### 問題 D — Softmax 沒有獨立的 τ 超參數
ε 和 τ 目前共用同一個 slider，使用者無法分別控制兩種策略的探索強度。

## 一、修正 epsilonToTau（reinforceEngine.js）

### 現況
```js
function epsilonToTau(epsilon) {
  if (epsilon === 0) return 0.01;
  return 1 / (epsilon + 0.1) - 0.5;   // ❌ ε↑ → τ↓（越貪婪）
}
```

### 修正目標
ε 越大 → 探索越強 → τ 越大（Softmax 越平滑）

### 建議公式
```js
function epsilonToTau(epsilon) {
  return Math.max(0.01, epsilon * 2);  // ε=0 → τ=0.01（幾乎確定性），ε=1 → τ=2（近均等）
}
```

> 係數可調，核心是「單調遞增」。若要與 ε-greedy 的探索強度視覺上匹配，
> ε=0.1 對應的 τ=0.2 在常見 Q 值範圍（0~50）下會給出合理的分散度。

## 二、新增純函數供 qualityCharts 呼叫（reinforceEngine.js）

qualityCharts 需要獨立計算機率（不依賴當前 Agent 狀態），新增兩個純函數：

```js
// 純函數版，不依賴全域 Epsilon，由呼叫端傳入
function calcEGreedyProbs(qArray, epsilon) {
  const n = qArray.length;
  if (qArray.every(v => v === 0)) return new Array(n).fill(1 / n);
  const best = qArray.indexOf(Math.max(...qArray));
  const probs = new Array(n).fill(epsilon / (n - 1));
  probs[best] = 1 - epsilon;
  return probs;
}

function calcSoftmaxProbs(qArray, epsilon) {
  const tau = epsilonToTau(epsilon);
  const exps = qArray.map(q => Math.exp(q / tau));
  const sum  = exps.reduce((a, b) => a + b, 0);
  return exps.map(e => e / sum);
}
```

## 三、改寫 generateDiscreteColorscale（qualityCharts.js）

### 現況
```js
function generateDiscreteColorscale(actionSize) {
  const colorscale = [[0, 'black']];          // A0 寫死黑色
  for (let i = 1; i < actionSize; i++) {
    const hue = ((i - 1) * 360 / (actionSize - 1)) % 360;
    colorscale.push([i / (actionSize - 1), hsvToRgb(hue, 1, 1)]);
  }
  return colorscale;
}
```

### 修正：A0 從 hue=0°（紅）開始，全部均分色環
```js
function generateDiscreteColorscale(actionSize) {
  if (actionSize === 1) return [[0, hsvToRgb(0, 1, 1)]];
  return Array.from({ length: actionSize }, (_, i) => {
    const hue = (i * 360 / actionSize) % 360;
    return [i / (actionSize - 1), hsvToRgb(hue, 1, 1)];
  });
}
```

**結果（3 動作）：** A0=紅(0°)、A1=綠(120°)、A2=藍(240°)  
**結果（4 動作）：** A0=紅(0°)、A1=黃(90°)、A2=青(180°)、A3=藍紫(270°)

- `generateQLineSlice()`：用 `generateDiscreteColorscale`，**免改**

## 五、改寫 generateQBarSlice（qualityCharts.js）

### 目標外觀
- 每個動作 3 根柱子，barmode: 'group'
- 左 Y 軸：Q 值（現有）
- 右 Y 軸：機率（0~1）
- 柱子外觀：

| 柱子 | 顏色 | 透明度 | 邊框 | Y 軸 |
|------|------|--------|------|------|
| Q 值 | 動作原色（實心） | 1.0 | 無 | 左 |
| ε-greedy 機率 | 動作原色偏深（HSV V=0.6） | 1.0 | 無 | 右 |
| Softmax 機率 | 動作原色偏淺（HSV S=0.4） | 0.6 | 細白框 | 右 |

> 偏深/偏淺用同色的不同 S/V 變體，視覺上是「同色系三兄弟」，
> 不需要圖例就能感覺到「這三根是同一個動作的三個面向」。

### 讀取參數
qualityCharts.js 需要能讀到：
- `Epsilon`（全域，index.html 已定義）
- `currentStrategy`（全域，index.html 已定義）

兩者目前都是 index.html 的全域變數，qualityCharts 在同一頁面載入，**直接讀取，無需傳參**。

### 概念程式碼
```js
function generateQBarSlice() {
  const qArr    = getQArrayForChart(focusState);
  if (!qArr) return;

  const epsilon = typeof Epsilon !== 'undefined' ? Epsilon : 0.1;
  const egProbs = calcEGreedyProbs(qArr, epsilon);
  const smProbs = calcSoftmaxProbs(qArr, epsilon);
  const colors  = getActionColors(action_size); // 從 generateDiscreteColorscale 抽出

  const traces = [];
  for (let a = 0; a < action_size; a++) {
    const baseColor  = colors[a];
    const darkColor  = adjustHSV(baseColor, 1, 0.6);   // 偏深
    const lightColor = adjustHSV(baseColor, 0.4, 1);   // 偏淺

    // Q 值柱（左 Y 軸）
    traces.push({ x: [a], y: [qArr[a]], type: 'bar', name: `Q a${a}`,
      marker: { color: baseColor }, yaxis: 'y' });

    // ε-greedy 機率柱（右 Y 軸）
    traces.push({ x: [a], y: [egProbs[a]], type: 'bar', name: `ε a${a}`,
      marker: { color: darkColor }, yaxis: 'y2' });

    // Softmax 機率柱（右 Y 軸）
    traces.push({ x: [a], y: [smProbs[a]], type: 'bar', name: `SM a${a}`,
      marker: { color: lightColor, opacity: 0.6,
                line: { color: 'white', width: 1 } }, yaxis: 'y2' });
  }

  Plotly.newPlot('p1-bars-value', traces, {
    title: '動作價值與選擇機率',
    xaxis: { title: '動作', tickvals: [...Array(action_size).keys()],
             ticktext: [...Array(action_size).keys()].map(i => `a${i}`) },
    yaxis:  { title: 'Q 值' },
    yaxis2: { title: '選擇機率', overlaying: 'y', side: 'right',
              range: [0, 1], showgrid: false },
    barmode: 'group', showlegend: false,
    margin: { t: 30, b: 40, l: 50, r: 50 }
  }, { displayModeBar: false });
}
```

## 六、τ slider 獨立化（新增）

### 設計決策
- `epsilonToTau()` 函數整個刪除，τ 改為獨立全域變數 `Tau`
- `calcSoftmaxProbs(qArray, epsilon)` 改簽名為 `calcSoftmaxProbs(qArray, tau)`
- `softmaxStrategy()` 改為直接讀 `Tau`

### UI 改動（index.html）
- 在探索策略區塊：
  - 選 ε-greedy → 顯示 ε slider，隱藏 τ slider
  - 選 Softmax → 顯示 τ slider，隱藏 ε slider
- τ slider 規格：
  - 範圍：0.1 ~ 20，步進 0.1，預設值 **5**
  - 顯示格式：`τ = 5.0`
  - τ=5 在 Q 值 0~50 尺度下可給出有意義的分散分布

### Softmax 的 Q 值溢出問題
Softmax 在訓練後期 Q 值差距已大，機率自然收斂到接近 1（確定性選擇），
這是正確行為，不需要修正。τ slider 讓使用者在訓練初期可以手動調高 τ 增加探索，
後期若想觀察確定性選擇直接降低 τ 即可，使用者自己控制。
