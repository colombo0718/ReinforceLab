# RR 假游標層施工計畫

## 目標

在 RR 前端加上一層可由 Playwright 控制的展示 overlay，優先服務論文教學影片錄製與平台導覽展示。

本次先做錄影版 MVP，提供以下能力：

1. 假游標移動
2. 點擊波紋
3. hover 高亮
4. 拖曳路徑
5. 標紅框聚焦
6. 操作節奏控制

本次不做：

- 角落步驟提示文字
- 人機共控
- shadow mode
- Agent 操作描述層完整規格

---

## 設計原則

- 盡量不碰 `reinforceEngine.js` 與主訓練流程
- 先做成獨立展示層，預設關閉
- 讓 Playwright 可用簡單 API 呼叫
- 不影響一般使用者正常操作
- 即使不用 Playwright，也能在瀏覽器 console 手動測試

---

## 實作範圍

### 1. Overlay 骨架

在主頁最上層加入一個固定定位的 overlay 容器，例如：

- `#rr-demo-overlay`

內部可分成幾層：

- 假游標層
- 點擊波紋層
- 拖曳軌跡層
- 紅框聚焦層

CSS 原則：

- `position: fixed`
- `inset: 0`
- `pointer-events: none`
- 高 `z-index`
- 所有動畫都只負責展示，不攔截操作

---

### 2. 前端控制 API

建立一個全域控制物件，例如：

```js
window.AgentVisualizer = {
  enable(),
  disable(),
  moveTo(x, y, options),
  click(x, y, options),
  hoverRect(rect, options),
  focusRect(rect, options),
  dragPath(points, options),
  clearFocus(),
  clearTrail(),
  setSpeed(multiplier),
}
```

這一層只負責把操作演出來，不負責真的點擊頁面。

---

### 3. 元素定位 helper

為了減少 Playwright 腳本端自己計算座標，補一層 selector 導向 helper：

```js
moveToElement(selector, options)
clickElement(selector, options)
focusElement(selector, options)
highlightElement(selector, options)
```

前端端自行透過 `getBoundingClientRect()` 計算位置與框線。

好處：

- 腳本比較短
- 版面微調時較不容易失效
- 更適合錄影腳本重播

---

### 4. 標紅框聚焦

這是本次 MVP 的核心能力之一。

需要支援兩種模式：

1. `focusRect(rect)`：直接以座標框選
2. `focusElement(selector)`：直接框 DOM 元件

預期效果：

- 紅色描邊
- 微弱呼吸動畫
- 可設定 padding
- 可設定圓角
- 不遮擋畫面內容

典型用途：

- 框住 `📊儀錶`
- 框住 `🔬分析`
- 框住某張圖表
- 框住左側遊戲 iframe 區

---

### 5. 點擊波紋與拖曳表現

#### 點擊波紋

- 游標先移動到目標位置
- 點擊瞬間出現波紋
- 可選擇搭配游標縮放或按壓效果

#### 拖曳路徑

- 游標依序沿路徑點移動
- 畫出淡色拖曳線
- 拖曳完成後可自動淡出

---

### 6. 操作節奏控制

提供速度倍率控制，例如：

- `0.5x`
- `1x`
- `1.5x`

主要影響：

- 游標移動動畫時長
- 點擊波紋播放速度
- 聚焦框顯示節奏
- 拖曳播放速度

用途：

- 除錯時放慢節奏
- 正式錄影時使用較順的播放節奏

## Playwright 串接方式

預計採用最輕量的做法：Playwright 真正操作頁面時，同步呼叫前端展示 API。

例如：

```js
await page.evaluate(() => window.AgentVisualizer.moveToElement('#loadGame'));
await page.click('#loadGame');
```

或：

```js
await page.evaluate(() => window.AgentVisualizer.clickElement('#loadGame'));
await page.click('#loadGame');
```

之後若確認這套好用，再整理成共用 helper。

## 驗證方式

第一階段先做本地驗證，不直接綁完整錄影流程。

驗證項目：

- 開頁後能從 console 手動呼叫 API
- 假游標能正確移動
- 紅框能框 tab / 按鈕 / 圖表 / iframe 區
- 全屏切換後位置仍正確
- 切換右側 tab 後 focus 位置仍正確

第二階段再接最小 Playwright demo。

## 風險與限制

### 1. iframe 內元素聚焦限制

父頁無法直接框到 iframe 內部元素，除非：

- 只框整個 iframe 外框
- 或未來由子頁另外配合提供對應 overlay 能力

### 2. 全屏切換後座標可能需要重算

左側全屏 / 半屏切換後，部分元素位置會改變，focus 與游標移動需重新取座標。

### 3. 動態載入內容需要等待

像 `docs/tutorial.html`、`docs/gamelist.html` 這類 fetch 後注入的內容，在錄影腳本中可能需要等待載入完成再聚焦。

### 4. 滾動與縮放影響

若畫面有滾動或 viewport 尺寸變化，應以當前 viewport 的實際座標計算位置。

---

## 本次實作判斷

這一版重點不是做完整共控系統，而是先完成一個對論文錄影最有幫助的最小展示層。

最有價值的兩個核心能力是：

- 假游標
- 標紅框聚焦

這兩者最直接改善教學影片的可看性，也最符合目前時程與穩定性需求。
