# 雙向觀察的共控平台 UI 設計思維

## 起點

Playwright 很適合自動化操作，但畫面上沒有可見游標——觀眾看到頁面突然被點、突然切換，不知道腳本在做什麼。

**核心矛盾：Playwright 會操作，但不會表演。**

---

## 六層架構

### 第一層：可視化
做一個「假游標層」，讓腳本的操作行為能被人看見。
- 假滑鼠箭頭、點擊波紋、步驟提示文字
- Playwright 負責真操作，假游標層負責把操作演給人看

### 第二層：雙介面
平台不只給人用，也給腳本／Agent 用。
- Human UI：滑桿、按鈕、圖表
- Agent UI：語意化控制介面（selector 以外的東西）

### 第三層：語意化控制
Agent 不能只靠 DOM selector，平台應暴露語意：
- 這頁有哪些重要元件、各自的意義是什麼
- 哪些操作安全、哪些危險、哪些有順序限制

**平台不只暴露畫面，也要暴露語意。**

### 第四層：共控
人與 AI 不是輪流使用，而是同時協作：
- AI 即時決策，人動態調參
- AI 持續運行，人隨時介入修正
- 人示範一部分，AI 延續一部分

類比自動駕駛：AI 夠強，但人還不能完全退出。

### 第五層：雙向觀察
不只人看 AI，AI 也看人：
- AI → 人：假游標 / 可視化示範
- 人 → AI：側錄 / shadow mode，記錄使用者操作路徑供 AI 分析

### 第六層：教、練、測、析
同一套機制支撐四種應用：
| 模式 | 說明 |
|------|------|
| AI 示範教學 | AI 透過腳本操作平台，動態生成教學內容 |
| AI 實作檢核 | AI 出題，人操作，AI 在背景驗證結果與順序 |
| 行為分析 | 累積使用路徑、卡點、常見錯誤，優化 UI 與教材 |
| 人機協作 | 人設高層策略，AI 執行細節 |
